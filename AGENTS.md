# AGENTS.md

## Project Summary

Task Tracker API is a Module 5 learning repository for a small FastAPI task tracker. The app provides task CRUD endpoints, a health endpoint, a static browser task board, overdue filtering, and an in-memory activity log. The active persistence layer is process memory in `app/storage.py`, so task and activity state resets when the process restarts. The project does not currently include authentication or database-backed storage (`README.md`, `app/main.py`, `app/storage.py`, `frontend/index.html`).

## Tech Stack

- Python 3.10 or newer is documented in `README.md`.
- FastAPI serves the API and the static frontend (`app/main.py`, `app/routes.py`).
- Pydantic models define request and response validation (`app/models.py`).
- Uvicorn runs the development server (`requirements.txt`, `README.md`).
- python-dotenv loads `.env` values (`app/main.py`, `requirements.txt`).
- pytest and FastAPI TestClient cover the API (`requirements.txt`, `tests/`).
- The frontend is a single self-contained HTML/CSS/JavaScript file served at `/` (`frontend/index.html`, `app/main.py`).

## Supported Commands

Run commands from the repository root.

Create and activate a virtual environment on Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Install dependencies:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Run the development server:

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Run all automated tests:

```bash
python -m pytest
```

Run tests with verbose output:

```bash
python -m pytest -v
```

CI currently installs dependencies from `requirements.txt` and runs:

```bash
pytest -v --tb=short
```

## Business Rules Visible in Code

- Task statuses are `ToDo`, `InProgress`, and `Done` (`app/models.py`).
- Task priorities are `Low`, `Medium`, and `High` (`app/models.py`).
- Creating a task defaults `status` to `ToDo`, `priority` to `Medium`, `description` to an empty string, and `assignee`/`due_date` to `None` when omitted (`app/models.py`, `tests/verify_a.py`).
- Task titles are required, trimmed, must not be blank, and must not exceed 200 characters (`app/models.py`, `tests/test_tasks.py`, `tests/verify_a.py`).
- Unknown request fields are rejected because Pydantic models use `extra="forbid"` (`app/models.py`, `tests/test_tasks.py`, `tests/verify_a.py`).
- Valid status transitions on update are only `ToDo -> InProgress`, `InProgress -> Done`, and `Done -> InProgress` (`app/business_rules.py`, `tests/test_tasks.py`).
- Same-status updates and transitions outside the allowlist return HTTP 422 when `status` is included in a PATCH request (`app/business_rules.py`, `tests/test_tasks.py`).
- List tasks may be filtered by `status`, `priority`, and `overdue` query parameters (`app/main.py`, `app/storage.py`, `tests/test_tasks.py`).
- A task is overdue when it has a `due_date` earlier than today's UTC date and its status is not `Done` (`app/storage.py`, `frontend/index.html`, `tests/test_tasks.py`).
- Task IDs and activity IDs are UUID strings generated by the storage layer (`app/storage.py`).
- Missing task lookups, updates, and deletes return HTTP 404 with a message that includes the requested ID (`app/main.py`, `tests/test_tasks.py`).
- The activity log records task creation, meaningful updates, status changes, and deletion (`app/storage.py`, `README.md`, `tests/test_tasks.py`).
- PATCH requests that do not change any stored value return the existing task and do not add activity entries (`app/storage.py`, `tests/test_tasks.py`).
- Activity entries are returned newest first and can be filtered to one task (`app/storage.py`, `tests/test_tasks.py`).
- Demo tasks seed on startup unless `APP_ENV=test`, pytest is loaded, or tasks already exist (`app/main.py`).
- Tests reset in-memory storage before and after each test (`tests/conftest.py`).
